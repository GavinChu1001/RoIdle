# 冒险页技能 DPS 与副本入口设计

## 背景

当前冒险页承担了战斗、目标提示、地图推进和阶段反馈等多种职责，但玩家真正需要持续观察的信息不够集中：

- 当前目标里同时出现 Boss 进度和首领位置，信息重复，容易分散注意力。
- 技能系统已经成为主要输出来源，但玩家看不到每个技能的实际输出贡献。
- 后续准备增加副本玩法，需要一个清晰入口，但不能让冒险页变成复杂菜单页。

这次设计目标是先提升战斗反馈闭环：玩家在冒险页能看清 Boss 推进和技能输出，并能从冒险页进入独立副本页。

## 目标

1. 冒险页当前目标只显示 Boss 进度，删除“当前首领位置”。
2. 冒险页右侧面板新增技能 DPS 模块，展示最近 30 秒内各技能的输出表现。
3. 新增副本入口，但副本内容放在独立页面中，不挤占冒险页主要战斗区域。
4. 第一版副本只包含“每日材料副本”和“Boss 试炼”两个方向，先搭清楚结构。
5. 复用现有战斗和奖励结算能力，避免一次性重做一套副本战斗系统。

## 非目标

- 不在本轮加入排行榜、公会、组队或多人副本。
- 不做复杂副本地图、路线选择或 roguelike 事件。
- 不重做技能系统，只增加输出统计展示。
- 不调整技能数值、怪物难度或装备掉落。
- 不把副本入口做成冒险页的大型卡片堆叠。

## 用户体验设计

### 冒险页目标区

当前目标区只保留 Boss 进度：

- 显示当前地图 Boss 进度百分比或进度条。
- 保留挑战 Boss 的相关操作。
- 删除“当前首领位置”这类位置文本。

这样冒险页目标更像“我离下一次阶段突破还有多远”，不会和地图信息重复。

### 技能 DPS 面板

技能 DPS 放在冒险页右侧面板，使用最近 30 秒滚动统计：

- 每个技能显示名称、DPS、伤害占比。
- 按最近 30 秒总伤害从高到低排序。
- 没有技能伤害时显示空状态，例如“暂无技能伤害记录”。
- 面板只统计技能伤害，不混入普攻，方便判断技能强弱。
- 刷新频率要克制，避免技能高频触发时进一步拖慢页面。

这个模块的意义不是做精确战斗日志，而是给玩家一个直观判断：当前真正的主力技能是谁。

### 副本入口

冒险页只放一个轻入口，例如右侧面板中的“副本”按钮或小模块：

- 显示可进入状态。
- 可以提示今日次数或主要副本状态。
- 点击进入独立副本页面。

冒险页仍然以推图和战斗为主，副本不在这里展开全部内容。

### 副本页面

副本页面第一版包含两个副本卡片：

1. 每日材料副本
   - 定位：稳定补充装备成长材料。
   - 显示：今日次数、推荐战力、主要奖励、进入按钮。
   - 用途：让材料获取有明确日常目标，减少“去哪刷”的迷茫。

2. Boss 试炼
   - 定位：阶段战力检验。
   - 显示：推荐战力、首通或每日奖励、进入按钮。
   - 用途：给装备成长和技能强度提供可验证目标。

第一版副本页不追求内容量，而是先把入口、状态、奖励和战斗复用链路打通。

## 技术设计

### 技能伤害采样

在技能造成伤害的现有路径里记录轻量事件：

- 技能名
- 伤害值
- 时间戳

统计层只保留最近 30 秒数据，过期记录会被清理。这样不会让长时间挂机导致记录无限增长。

### DPS 计算

展示时按技能聚合最近 30 秒伤害：

- `skillDamage = sum(skill damage in window)`
- `skillDps = skillDamage / 30`
- `share = skillDamage / totalSkillDamage`

如果实际窗口未满 30 秒，仍按 30 秒口径显示，避免开战瞬间 DPS 数字过度跳动。

### UI 更新节奏

DPS 面板不跟随每次伤害立即重绘。建议使用节流或固定刷新间隔：

- 战斗伤害事件只写入统计缓冲。
- UI 每 1 秒左右读取一次统计结果。
- 切换页面或离开冒险页时不做无意义重绘。

### 副本状态

副本状态进入 `state` 的独立字段，至少包含：

- 每日材料副本剩余次数或已用次数。
- Boss 试炼首通状态或每日状态。
- 最近一次副本结果可以后续补充，本轮不强制。

每日重置可以复用项目里已有的日常任务/每日状态归一化思路。

### 副本战斗复用

副本第一版复用现有怪物、战斗、奖励结算能力：

- 每个副本定义推荐战力、怪物模板、奖励表。
- 进入副本时临时指定战斗目标或副本上下文。
- 结算时走已有奖励发放工具，减少重复逻辑。

如果现有战斗链路不适合直接承载副本，优先做一个很薄的副本适配层，不在第一版重写战斗核心。

## 数据与配置

新增或扩展的配置应该集中管理：

- 副本 id、名称、推荐战力、每日次数。
- 副本奖励预览和实际奖励。
- 副本怪物或 Boss 模板引用。
- DPS 面板展示数量上限，建议默认 5 个技能。

副本配置应当可读，方便后续继续增加金币副本、经验副本、职业试炼等内容。

## 验收标准

1. 冒险页当前目标只显示 Boss 进度，不再显示当前首领位置。
2. 右侧技能 DPS 面板能展示最近 30 秒技能输出排行。
3. 技能频繁触发时，页面不会因为 DPS 面板每次伤害都重绘而明显变卡。
4. 冒险页有清晰副本入口，点击可以进入独立副本页面。
5. 副本页面能看到“每日材料副本”和“Boss 试炼”的基础信息与进入按钮。
6. 新增状态能被新存档正常初始化，并能在存档合并/归一化时保持稳定。
7. `npm test` 和 `npm run check` 通过。

## 风险与处理

- 风险：技能 DPS 统计加剧当前技能高频触发带来的卡顿。
  - 处理：事件采样轻量化，UI 固定刷新，不跟随每次伤害重绘。

- 风险：副本页第一版内容太薄，玩家觉得只是多了两个按钮。
  - 处理：卡片必须显示次数、推荐战力、奖励预览和进入状态，让目标明确。

- 风险：副本复用现有战斗链路时牵动太多旧逻辑。
  - 处理：先用薄适配层接入，不把副本逻辑写进大型核心函数里。

## 实施顺序建议

1. 先改冒险页当前目标和右侧 DPS 展示，因为这部分反馈最直接。
2. 再补技能伤害采样和滚动统计，确保性能可控。
3. 最后搭副本页面、入口和第一版副本配置。
4. 每一步都补最小必要测试，避免 UI 和状态归一化回归。
