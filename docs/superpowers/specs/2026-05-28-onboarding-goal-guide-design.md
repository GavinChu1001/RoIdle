# Rune Frontier Idle 新手引导与目标手册设计

日期：2026-05-28

## 决策

下一阶段优先补齐玩家的目标感和反馈闭环。首版采用“短强引导 + 常驻目标手册”的混合方案：

- 前 3-5 分钟用轻量教程提示带玩家走完第一轮成长闭环。
- 教程结束后，由冒险页的“当前下一步”和任务页的完整目标手册继续提供方向。
- 服务端保存安全可以作为同阶段的小补丁另行处理；state 事件化和渲染自动触发不放进本轮范围。

## 目标

- 让新玩家知道开局下一步该做什么。
- 让玩家在第一轮体验里理解核心循环：打怪、领奖、变强、推进 Boss。
- 复用现有任务、日常、成就和冒险页结构，不重写任务系统。
- 兼容旧存档，不破坏现有进度。
- 为后续目标系统、活动、赛季等长期玩法留出清晰入口。

## 非目标

- 不做完整事件总线或 state 事件化。
- 不重构 `renderAll()` 或全局 `window.state` 模式。
- 不重写现有主线任务、日常目标、成就系统。
- 不做全屏强制遮罩教程。
- 不拦截所有点击或强制玩家只能按教程操作。
- 不在首版加入社交、排行榜、公会、活动或赛季。

## 推荐方案

新增一个薄引导层，放在现有任务和页面系统上方。

该层负责：

- 保存教程是否完成、是否跳过、当前教程步骤。
- 根据现有 `state` 推导新手目标完成度。
- 选择当前最推荐的下一步。
- 为冒险页和任务页提供渲染数据。

该层不负责：

- 复制击杀、装备、奖励、Boss 等进度。
- 发放另一套独立奖励。
- 替代现有任务系统。

## 玩家体验流程

首版强引导结束点定为“第一轮成长闭环”。

流程：

1. 欢迎玩家，说明玩家是露恩学徒，从南门开始冒险。
2. 引导进入冒险页，完成第一段击杀目标。
3. 提醒领取第一次奖励。
4. 引导完成一次变强动作，例如装备新物品、强化武器，或完成一次明确成长。
5. 回到冒险页，展示本地图 Boss 进度。
6. 强引导结束，切换为常驻目标手册。

交互原则：

- 每次只提示一个动作。
- 提示短、按钮明确。
- 玩家可以跳过教程。
- 跳过教程后不再显示强引导，但目标手册仍然显示。
- 教程提示不锁死页面，避免和放置玩法的自由节奏冲突。

## 界面结构

界面分三层。

### 教程提示

只在强引导阶段出现。它显示：

- 当前要做什么。
- 为什么现在要做。
- 一个主行动按钮。
- 一个跳过教程按钮。

教程提示不承载长期目标列表。

### 冒险页当前下一步

冒险页右侧或旁侧信息区显示一条最推荐目标。它显示：

- 目标标题。
- 简短说明。
- 为什么值得做。
- 完成后的收益或奖励预期。
- 前往按钮。

冒险页只显示一条当前最重要的下一步，避免信息堆叠。

### 任务页目标手册

任务页顶部新增“新手目标”区块，放完整目标列表。现有主线任务、日常目标、成就继续保留在下方。

新手目标卡片显示：

- 标题。
- 当前状态：未开始、进行中、已完成。
- 简短说明。
- 奖励或收益说明。
- 可用时的前往按钮。

## 数据结构

新增 `state.onboarding`：

```js
onboarding: {
  version: 1,
  tutorialCompleted: false,
  skipped: false,
  currentStepId: "welcome",
  completedStepIds: [],
  dismissedHintIds: []
}
```

旧存档没有 `onboarding` 字段时，加载时自动补默认值。

目标完成度尽量从现有状态推导：

- 击杀目标读取 `totalKills`、`areaKills`、`quests` 或当前地图进度。
- 奖励领取读取现有任务、战利品或离线奖励状态。
- 装备和成长读取 `inventory`、`equipped`、强化相关状态和角色状态。
- Boss 目标读取当前地图、Boss 状态和现有进度文本。

这样可以避免维护两套互相漂移的进度。

## 模块设计

新增模块：

- `src/systems/onboarding.js`
  - 默认 onboarding 状态。
  - normalize 函数。
  - 新手目标静态配置。
  - 目标完成度计算。
  - 当前推荐目标选择。
  - 教程步骤推进判断。

- `src/ui/onboardingGuide.js`
  - 教程提示渲染。
  - 冒险页“当前下一步”卡片渲染。
  - 任务页“新手目标”区块渲染。

接入现有代码：

- `game.js`
  - `createDefaultState()` 增加 `onboarding` 默认值。
  - 存档合并和规范化流程补 `normalizeOnboarding()`。
  - 关键动作后调用教程推进逻辑。

- `src/ui/taskPage.js`
  - 在主线任务、日常目标、成就之前渲染新手目标区块。

- 冒险页渲染
  - 将现有简短任务提示区域升级为“当前下一步”，或在同一区域旁侧新增该卡片。

## 教程步骤建议

首版步骤：

1. `welcome`
   - 目标：让玩家知道自己从南门开始。
   - 行动：前往冒险页。

2. `start_adventure`
   - 目标：开始击杀第一批魔物。
   - 完成条件：累计击杀达到一个很小的阈值，或现有南门主线任务产生进度。

3. `claim_first_reward`
   - 目标：领取第一次明确奖励。
   - 完成条件：领取一个新手相关任务奖励，或领取首批战利品。

4. `grow_once`
   - 目标：完成一次变强行为。
   - 完成条件：装备变化、强化成功，或另一个明确成长动作完成。

5. `see_boss_goal`
   - 目标：回到冒险页看到 Boss 进度。
   - 完成条件：当前推荐目标切到 Boss 推进；随后标记 `tutorialCompleted`。

## 错误处理与边界

- 如果玩家已经完成某个步骤，教程应自动跳到下一个未完成步骤。
- 如果玩家跳过教程，`skipped` 设为 `true`，强引导不再出现。
- 如果旧存档玩家已经很强，目标手册应优先显示适合当前进度的下一步，而不是强行回到新手步骤。
- 如果某个前往按钮对应页面暂时不可用，按钮应禁用或退化为文字提示。
- 如果目标完成度无法可靠判断，该目标应显示为未完成，但不能阻塞教程之外的游戏流程。

## 测试与验收

自动检查：

- 新增 onboarding 纯函数测试，覆盖默认状态、normalize、当前目标选择、完成度判断、跳过后行为。
- `npm run check` 通过。
- `npm test` 通过。

手动验收：

- 新存档能完整走通：开始冒险 -> 领取奖励 -> 变强一次 -> 看到 Boss 目标。
- 玩家可以跳过教程；跳过后强提示不再出现，目标手册仍可用。
- 旧存档能加载并自动补 `onboarding` 默认值，不丢装备、任务、地图和日志。
- 冒险页只显示一条清晰的当前下一步。
- 任务页能显示完整新手目标，且不影响原有主线任务、日常目标和成就。

首版成功标准：

一个完全不了解系统的新玩家，进入游戏后 3-5 分钟内应该知道在哪里打怪、为什么领奖、如何变强、下一个阶段目标是 Boss。

## 风险

- `game.js` 仍然很大，教程推进接入点要克制，避免把本轮变成架构重构。
- 如果“变强一次”的完成条件定义过宽，教程可能跳得太快；定义过窄，又可能卡住玩家。
- 冒险页空间有限，当前下一步卡片需要保持短小，避免挤压战斗信息。
- 目标手册如果奖励文案过多，会变成另一个任务列表；首版文案应强调“为什么做”。

## 第一实施切片

第一步保持小：

1. 新增 onboarding 默认状态和 normalize。
2. 新增目标配置和当前目标选择纯函数。
3. 在任务页顶部渲染新手目标区块。
4. 在冒险页渲染一条当前下一步。
5. 加入跳过教程状态。
6. 补纯函数测试并运行现有检查。

后续再加入更强的教程提示样式、按钮高亮和更细的步骤推进。
