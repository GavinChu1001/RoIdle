# 装备属性 V2 设计

日期：2026-05-28
项目：Rune Frontier Idle
状态：已确认设计，等待实施计划

## 背景

当前装备属性系统已经出现明显的臃肿和弱反馈问题：

- 部分属性进入展示、评分和汇总链路，但没有实际战斗效果，例如 `blockRate`、`antiCrit`。
- 多个属性语义接近，实际落在同一乘区或同一效果上，例如 `powerPct`、`combatPaceBonus`、`patrolEfficiency`。
- 六维属性价值差距过大，`STR/INT` 明显强于 `DEX/LUK`，导致装备词条选择缺少悬念。
- 若干机制词条只在狭窄场景生效，例如多目标、被击、越级，和放置游戏的长期挂机场景不匹配。
- 装备评分仍奖励部分低价值或无效属性，容易误导玩家。

V2 的目标不是继续修补单个词条，而是重建一套更清楚、更有取舍、更容易长期扩展的装备属性体系。

## 设计目标

1. 装备属性更少、更清晰，玩家能快速理解每个词条为什么有用。
2. 保留 RO 味道的六维属性，但让每个属性有明确职责。
3. 装备差异主要来自少量强感知机制词条，而不是大量小数值堆叠。
4. 所有展示、评分、生成、战斗生效链路必须一致。
5. 旧装备进入新体系时彻底重算，避免继续背负旧系统包袱。
6. 新体系优先服务当前放置玩法，Boss 和挂机场景都要有可感知收益。

## 非目标

- 不在本轮引入交易、赛季、公会、排行榜等社交系统。
- 不把装备系统做成复杂的暗黑式深度 build 系统。
- 不保证旧装备强化、卡片、随机词条的历史资产完整保留。
- 不追求一次性完成所有职业和技能平衡，只建立装备属性的新基线。

## 核心方向

采用混合流装备设计：

- 六维属性保留，用于提供 RO 风格和职业底盘。
- 普通词条提供稳定收益。
- 机制词条提供装备记忆点和配装趣味。
- 机制词条强度采用折中型：明显有感，但不让玩家因为没有某个机制就无法推进。

## 旧装备迁移

采用彻底重算策略。

旧装备迁移后保留：

- 装备部位
- 装备等级或掉落等级
- 稀有度、品阶、模板身份
- 必要来源标签，例如深渊、神话

旧装备迁移后重置：

- 当前基础属性
- 随机词条
- 特殊机制词条
- 强化、星炼、赋能
- 镶嵌卡片
- 评分
- 旧版无效或废弃属性

迁移补偿：

- 发放一次性重铸券。
- 重铸券用于让玩家在新系统中重新打造或重置核心装备。
- 补偿逻辑不做复杂资源折算，避免迁移代码变成第二套装备系统。

## 属性结构

### 六维属性

| 属性 | 新定位 |
| --- | --- |
| STR | 物理攻击，少量格挡强度 |
| INT | 魔法攻击，技能伤害 |
| AGI | 攻速，闪避 |
| VIT | 生命，防御，回复 |
| DEX | 暴击，命中，机制触发率 |
| LUK | 掉落，稀有掉落，幸运触发 |

要求：

- 每个六维都必须能解释给玩家听。
- `DEX` 不再只是弱化版攻击属性，应承担暴击和触发稳定性。
- `LUK` 必须成为刷宝流核心属性，至少提供有体感的掉落和稀有收益。

### 普通词条

输出类：

- 物理攻击
- 魔法攻击
- 攻速
- 暴击率
- 暴击伤害
- 技能伤害
- 首领伤害
- 最终伤害

生存类：

- 生命
- 防御
- 减伤
- 闪避
- 格挡
- 吸血
- 回复

经济类：

- 经验
- 金币
- 掉落
- 稀有掉落
- 材料数量
- 离线效率

### 机制词条

机制词条应少而清楚，且必须在挂机或 Boss 场景中有等效收益。

初始机制池：

- 回响：技能命中后追加一次较低倍率伤害。
- 溅射：多目标时造成范围伤害，单目标或 Boss 时转化为较低倍率单体追加伤害。
- 追击：普攻或技能后概率追加一次伤害。
- 格挡反击：格挡触发后减伤并反击。
- 处决：敌方低血量时提高伤害或触发追加伤害。
- 巡猎：提高挂机推进效率或普通战斗节奏。
- 寻宝：提高稀有掉落或触发额外奖励。

机制词条原则：

- 不出现只在极少场景才工作的词条。
- 不出现纯粹换名字的同乘区词条。
- 每个机制都要能在战斗日志、飘字或面板中被玩家感知。

## 废弃与合并

| 旧属性 | 处理 |
| --- | --- |
| `antiCrit` | 删除；抗暴语义不再作为独立装备属性保留 |
| `blockRate` | 保留为真正战斗属性，必须接入怪物攻击结算 |
| `powerPct` | 合并进统一的输出/战力词条，不再和节奏类重复 |
| `combatPaceBonus` | 与巡猎类效果统一命名和计算 |
| `patrolEfficiency` | 合并进巡猎或挂机效率，不再折半塞入 DPS 乘区 |
| `hitRate` | 合并到 `DEX` 或命中相关机制，不作为泛用装备词条优先保留 |
| `higherLevelDamageBonus` | 删除或并入挑战/首领类机制，避免极窄收益 |
| `meteorCounterChance` | 改造成稳定可感知的反击或追击机制 |
| `thornVitMultiplier` | 并入格挡反击或反伤机制 |

## 评分原则

装备评分必须只奖励真实生效的属性。

评分拆为几个维度：

- 综合评分：默认排序和快速判断。
- 输出评分：DPS、暴击、技能、Boss 伤害。
- 生存评分：生命、防御、减伤、闪避、格挡、回复。
- 刷宝评分：金币、掉落、稀有、材料、离线效率。
- 机制评分：回响、溅射、追击、反击、处决等。

评分不应掩盖构筑差异。机制词条可以提高综合分，但需要在详情中展示具体价值，避免所有装备最后只剩一个大数字。

## 数据与代码边界

需要统一调整以下链路：

- 装备模板和随机词条池
- 装备实例生成与旧装备 normalize
- `computeEquipmentFullStats`
- `computeStats`
- 战斗结算，特别是怪物攻击、格挡、反击、追击、溅射
- 装备评分
- 装备详情、角色面板、词条说明
- 存档迁移和一次性重铸券发放
- 测试脚本中的装备、战斗、迁移断言

实施时应优先抽出属性配置表，避免继续把属性定义散落在 `game.js`、UI 和评分逻辑中。

## 测试要求

至少覆盖：

- 旧装备迁移后旧属性被清理，新属性被重算。
- 强化、卡片、旧随机词条按设计被重置。
- 迁移只发放一次重铸券。
- `blockRate` 在战斗中实际降低伤害或触发格挡逻辑。
- `antiCrit` 不再出现在生成、评分、展示链路。
- `LUK` 能提高掉落或稀有收益。
- 机制词条在 Boss 和挂机普通战斗中都有可验证收益。
- 装备评分不再奖励无效属性。

## 实施拆分建议

1. 定义 V2 属性表和废弃属性表。
2. 改造装备生成和 normalize，让新装备只产出 V2 属性。
3. 写旧装备迁移逻辑，并发放一次性重铸券。
4. 接入战斗生效，优先实现格挡、追击、溅射等核心机制。
5. 重写装备评分。
6. 更新角色面板、装备详情和词条说明。
7. 补核心迁移、评分、战斗测试。

## 验收标准

- 新装备不再生成 `antiCrit` 等废弃属性。
- 装备详情中展示的每个属性都能在战斗、成长或经济系统中生效。
- 旧存档加载后不会崩溃，旧装备按 V2 规则重算。
- 玩家获得一次性重铸券，并且不会重复领取。
- 核心测试、语法检查通过。
- 装备选择从“看总战力”变成至少能区分输出、生存、刷宝、机制四类倾向。
