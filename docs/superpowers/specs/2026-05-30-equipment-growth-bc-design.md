# Equipment Growth B+C Design

## 背景

当前装备系统同时使用四条成长轴：

- 装备线：古代英雄、OS、信念、冰川、忏悔、善恶、星云、莫卡迪斯、次元等。
- 阶段 / T阶：同一装备线内的进阶阶段，例如 OS 到 OS-AD。
- 稀有度：普通、精良、稀有、史诗、古代、传说、暗金、神话。
- 内部等级：`item.level` / `dropLevel`，用于生成和进阶后的数值缩放。

这几条轴现在都能影响强度，但对玩家的表达不够清楚。列表里去掉装备 Lv 后，内部等级仍然会参与计算，因此需要把装备成长整理成更稳定的规则。

## 目标

采用“B+C”混合方案：

- B：保留装备线、阶段、稀有度三轴，让玩家能理解装备身份和成长路线。
- C：新装备逐步去等级化，装备强度主要来自线、阶段、T阶、稀有度、精炼、赋能、共鸣和精通。
- 旧装备软迁移：不立即重算旧存档装备，避免玩家已有战力突然变化。

## 非目标

- 不删除 `item.level` / `dropLevel` 字段。它们仍用于旧装备兼容、来源记录和迁移判断。
- 不一次性重算玩家已有装备。
- 不把所有装备线重做成真实 RO 官方数值，只保证成长层级更接近 RO 装备路线感。
- 不在本设计中调整职业、技能、怪物或境界系统。

## 核心规则

装备最终强度应逐步改成：

```text
装备基础模板
× 装备线阶段倍率
× T阶倍率
× 稀有度倍率
× 品质浮动
× 精炼 / 星炼 / 赋能
× 套装 / 共鸣 / 路线精通
```

新装备不再把 `item.level` 作为主要成长倍率。`dropLevel` 只作为“来源强度”和旧数据兼容字段。

## 数据表达

装备应明确区分这些字段：

- `series`：装备线，例如 `ancientHero`、`os`、`fides`、`glacier`。
- `growthTier`：大阶段，例如 `T3`、`T6`、`T9`。
- `upgradeStage`：线内进阶序号，例如 0、1、2。
- `grade`：线内阶段 id，例如 `os`、`osAd`、`vivatus`。
- `rarity`：随机品质。
- `dropLevel`：来源强度，后台兼容字段。
- `legacyPowerSnapshot` 或同类标记：旧装备是否保留旧数值。

## 新装备生成

新生成装备使用 `series + growthTier + upgradeStage + rarity` 计算基础属性。

要求：

- `growthTier` 决定基础跨度。
- `upgradeStage` 决定该线内是否处于后续改造层。
- `rarity` 决定品质倍率、词条容量、卡槽上限和专属效果。
- `dropLevel` 可以记录地图来源，但不再直接作为主要乘区。

## 旧装备软迁移

旧装备不立即重算。

迁移策略：

- 加载旧装备时保留现有数值。
- 如果装备缺少新字段，则补齐 `series`、`growthTier`、`upgradeStage`、`grade` 的安全默认值。
- 如果旧装备已有异常高/低数值，不在加载时修正。
- 当旧装备执行下一次进阶时，进入新规则：保留精炼、赋能、卡片、锁定、已拥有词条；重算基础成长属性；再补齐目标稀有度权益。

这样可以避免旧玩家战力突降，同时让后续成长进入统一轨道。

## 装备进阶

进阶不再只是给旧属性乘 `statMultiplier`。

进阶流程：

1. 检查材料和金币。
2. 读取下一阶段配置。
3. 保留玩家投入项：精炼、赋能、卡片、锁定、收藏状态、已有随机词条。
4. 根据目标 `series + growthTier + upgradeStage` 重算基础成长属性。
5. 根据目标 `rarity` 补齐稀有度权益。
6. 写入新的 `grade`、`progressionLabel`、`growthTier`、`upgradeStage`。
7. 保存并刷新 UI。

## 稀有度权益补齐

当进阶目标稀有度高于当前稀有度时，应补齐对应品质权益，而不是只改 `rarity` 文本。

补齐规则：

- 稀有：确保随机六维进入稀有区间。
- 史诗：补 1 个史诗特殊词条。
- 古代：确保至少 1 个卡槽。
- 传说：补职业技能强化效果。
- 暗金：补暗金专属套装增幅。
- 神话：补神话被动。

补齐必须幂等：同一件装备重复进阶、加载或修复时，不应重复获得同一类权益。

## 共鸣与阶段

当前共鸣主要按同线件数触发。新规则加入阶段门槛：

- 同线 4 件：基础共鸣。
- 同线 4 件，平均 `upgradeStage >= 1`：强化共鸣。
- 同线 5 件，平均 `upgradeStage >= 2`：完整共鸣。
- 精炼总和仍保留职业技能联动。

这样同一装备线的长期进阶会比单纯凑齐低阶件更有价值。

## 路线精通

路线精通继续保留，但应作为材料溢出和长期养成，不抢主装备进阶的优先级。

规则建议：

- `basic` 材料：前期进阶和精通 1-5。
- `advanced` 材料：中段进阶和精通 6-10。
- `core` 材料：关键进阶优先，精通 11+ 才大量消耗。
- UI 文案提示：建议先完成当前主装备阶段，再投入路线精通。

## UI 表达

装备主卡片不显示 `Lv.xx`。

建议显示：

```text
黯淡冰晶战刃
传说 · T7 · 冰晶线 · 阶段 3
```

详情显示：

- 装备线：冰晶。
- 阶段：黯淡冰晶。
- T阶：T7。
- 品质：传说。
- 来源：深渊钟塔或对应地图/难度。
- 下一阶段：材料、金币、主要提升。

避免把内部 `item.level` 称为等级。若必须保留调试信息，使用“来源强度”。

## 测试重点

- 新装备生成不依赖 `item.level` 作为主要乘区。
- 旧装备加载后战力不被重算。
- 旧装备进阶后进入新规则，并保留精炼、赋能、卡片。
- 稀有度提升会补齐对应权益，且不会重复补。
- 共鸣会根据同线件数和平均阶段触发不同层级。
- 装备列表、离线收益、详情主要 UI 不显示装备 `Lv.xx`。

## 分阶段实施

1. 增加成长计算入口，先不切换旧装备。
2. 增加稀有度权益补齐函数和测试。
3. 改造进阶流程，让进阶进入新成长计算。
4. 调整新装备生成，逐步减少 `item.level` 对属性的影响。
5. 调整共鸣阶段门槛。
6. 整理 UI 文案和详情展示。

## 验收标准

- 玩家看到的装备成长由“装备线 + 阶段 + T阶 + 稀有度”表达。
- 新装备不会因为隐藏等级而出现无法解释的强度差异。
- 旧装备不会在登录或加载时突然缩水。
- 进阶到高品质后，装备实际拥有对应品质权益。
- 共鸣鼓励持续进阶，而不是只凑低阶同线件。
