# 境界等级系统设计

日期：2026-05-29  
状态：设计已获用户口头确认，等待实现计划  
范围：Rune Frontier Idle 的长期在线成长系统

## 背景

当前游戏已经有几条成长线：

- BASE / JOB：角色基础等级与职业成长，主要由战斗经验推动。
- 转生：达到 BASE 上限后的重置突破，提升长期上限和稀有装备权重。
- 装备进度：从古代英雄、幻象、OS、信念、冰晶到莫卡迪斯/次元等装备层级推进。
- VIP、地图探索、技能成长、装备词条：提供局部加成和长期目标。

新增的“境界”系统应当补足一个缺口：玩家在线时有稳定、可见、不会被转生重置的长期成长。它不能压过装备，也不能变成另一个 BASE 等级。

## 目标

1. 玩家在线时自动积累“修为”。
2. 修为满后自动提升小境界等级。
3. 每 10 级需要一次手动突破，突破条件与现有战斗进度绑定。
4. 境界提供小幅常驻属性和阶段奖励。
5. 境界不吃离线收益，突出“在线修行”的存在感。
6. 旧存档自动兼容，默认获得境界初始状态。

## 非目标

- 不做突破失败率。
- 不做境界技能树。
- 不做排行榜。
- 不做每日修行任务。
- 不做付费加速。
- 不把境界经验加入离线奖励。
- 不重构 BASE/JOB、转生、离线收益或装备系统。

## 核心定位

境界是第三成长线：

```text
BASE / JOB = 战斗等级，短中期成长
转生 = 重置突破，提升上限
境界 = 在线修行，长期累积，不重置
```

境界应当带来“每天开着玩一会儿也在变强”的感觉，但单级收益必须足够轻，避免玩家只靠在线时长越过装备和战斗门槛。

## 推荐方案

采用“在线为主 + 战斗加速 + 突破卡点”的混合方案。

对比过的方案：

| 方案 | 规则 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| 纯在线修行 | 在线每秒涨修为 | 简单、稳定 | 与战斗关系弱，容易变成挂时长 | 不采用 |
| 战斗修行 | 击杀、Boss、地图进度给修为 | 与战斗强绑定 | 强者滚雪球，刷低图可能被滥用 | 不采用 |
| 在线为主 + 战斗加速 | 在线稳定涨，地图/难度/转生给轻微倍率，突破绑定战斗进度 | 适合 idle，在线与战斗都有意义 | 需要突破规则 | 采用 |

## 境界结构

境界总共 100 级，分 10 个大境界，每个大境界 10 级。

| 大境界 | 等级范围 | 对应阶段 | 主题 |
|---|---:|---|---|
| 初心境 | 1-10 | 新手、伊甸园 | 入门修行 |
| 符文境 | 11-20 | 一转二转成长 | 基础符文 |
| 英雄境 | 21-30 | 古代英雄 | 英雄共鸣 |
| 幻象境 | 31-40 | 幻象 / OS | 幻象回路 |
| 自动境 | 41-50 | 全自动 / OS-AD | 自动机甲 |
| 信念境 | 51-60 | 虚伪 / 活力信念 | 信念净化 |
| 冰晶境 | 61-70 | 雪花 / 冰晶 / 黯淡冰晶 | 冰晶凝核 |
| 星云境 | 71-80 | 灰狼后期 / 星云 | 星云回响 |
| 圣域境 | 81-90 | 凱渥寶樂格 / 莫卡迪斯 | 圣域武装 |
| 次元境 | 91-100 | 次元武器、终局 | 时间次元 |

显示规则：

- 小等级显示为 `境界名 Lv.X`。
- 例如总等级 36 显示为 `幻象境 Lv.36`。
- 总等级 100 达到当前 V1 上限。

## 修为获取

境界经验命名为“修为”。

基础公式：

```text
每分钟修为 = 10 × 地图倍率 × 难度倍率 × 转生倍率
```

地图倍率：

```text
地图倍率 = 1 + 当前地图序号 × 0.03
```

难度倍率：

| 难度 | 倍率 |
|---|---:|
| 普通 | 1.00 |
| 困难 | 1.20 |
| 深渊 | 1.45 |

转生倍率：

```text
转生倍率 = 1 + min(转生次数 × 0.03, 0.30)
```

积累条件：

- 角色在线。
- 游戏未暂停。
- 角色当前生命大于 0。
- 页面处于正常运行状态。

不积累条件：

- 离线结算。
- 暂停状态。
- 角色死亡且未恢复。
- 境界达到当前突破卡点但尚未突破。
- 境界达到 Lv100。

## 升级曲线

当前等级升级所需修为：

```text
所需修为 = round(120 × 当前等级 ^ 1.45 × 大境界系数)
大境界系数 = 1 + 当前大境界序号 × 0.22
```

大境界序号从 0 开始：

- 初心境 = 0
- 符文境 = 1
- 英雄境 = 2
- 以此类推

设计意图：

- Lv1-10 让玩家在当天能看到数次升级。
- Lv11-30 进入 1-3 天的成长节奏。
- Lv31-60 进入周级目标。
- Lv61-100 作为长线追求，不要求 V1 立刻填满所有内容。

## 突破规则

每 10 级需要突破一次。修为可以继续累计到当前等级所需上限，但不能跨过突破点。

突破点：

| 突破 | 条件 | 消耗 | 说明 |
|---|---|---|---|
| 10 -> 11 | BASE Lv20 | 无 | 早期教学突破 |
| 20 -> 21 | 击败森林 Boss | 少量金币 | 第一次战斗卡点 |
| 30 -> 31 | BASE Lv70 或完成关键转职进度 | 少量金币 | 进入古代英雄阶段 |
| 40 -> 41 | 解锁困难难度 | 中量金币 | 进入幻象/OS 后续 |
| 50 -> 51 | 击败古城 Boss | 古城首领魂或等价材料 | 进入信念阶段 |
| 60 -> 61 | 解锁深渊难度 | 深渊碎片或等价材料 | 进入冰晶阶段 |
| 70 -> 71 | 拥有任意 Lv230 装备或消耗冰晶材料 | 冰晶材料 | 进入星云阶段 |
| 80 -> 81 | 击败高阶 Boss 或消耗高级 Boss 魂 | Boss 魂 | 进入圣域阶段 |
| 90 -> 91 | 达成终局开放条件 | 终局材料 | 进入次元阶段 |

突破原则：

- 突破没有失败率。
- 突破条件尽量复用已有进度和材料。
- 如果某些高阶材料尚未实装，V1 可以先把高阶突破标记为“后续版本开放”，但不影响 Lv1-60 的系统上线。

## 属性奖励

每级给小幅常驻成长：

| 属性 | 每级奖励 |
|---|---:|
| 最大生命 | +0.25% |
| 物理攻击 | +0.12% |
| 魔法攻击 | +0.12% |
| 防御 | +0.08% |

这些奖励应进入最终属性计算，但倍率要和现有装备、卡片、称号等来源清楚分层，避免重复乘法导致数值膨胀。

每个大境界突破后额外给阶段奖励：

| 大境界 | 突破奖励 |
|---|---|
| 初心境 | BASE/JOB 经验 +2% |
| 符文境 | 金币 +2% |
| 英雄境 | 装备掉落 +1% |
| 幻象境 | 技能伤害 +2% |
| 自动境 | 离线效率 +2%，但境界本身仍不吃离线 |
| 信念境 | Boss 伤害 +2% |
| 冰晶境 | 材料掉落 +2% |
| 星云境 | 稀有品质权重 +1% |
| 圣域境 | P.ATK / S.MATK +1% |
| 次元境 | 最终伤害 +1.5% |

阶段奖励只在突破完成后生效。达到 10、20、30 等等级但未突破时，不提前获得下一阶段奖励。

## 数据模型

在存档中新增 `cultivation` 字段。

建议结构：

```javascript
cultivation: {
  level: 1,
  exp: 0,
  totalExp: 0,
  breakthroughLevel: 0,
  unlockedRealms: ["beginner"],
  lastTickAt: Date.now()
}
```

字段含义：

| 字段 | 含义 |
|---|---|
| level | 当前境界总等级，范围 1-100 |
| exp | 当前等级内修为 |
| totalExp | 历史累计修为，用于统计和成就 |
| breakthroughLevel | 已完成突破的最高 10 级节点 |
| unlockedRealms | 已解锁大境界 id，用于显示或未来扩展 |
| lastTickAt | 上次在线修为结算时间 |

兼容规则：

- 旧存档没有 `cultivation` 时，初始化为 Lv1、exp 0。
- 非法等级修正到 1-100。
- 非法 exp 修正到 0。
- 如果 `breakthroughLevel` 高于当前等级，修正为当前已完成的 10 级节点。

## 系统组件

建议新增独立模块，不塞进战斗结算。

候选模块：

```text
src/systems/cultivation/
  cultivationData.js
  cultivationSystem.js
```

职责划分：

| 模块 | 职责 |
|---|---|
| cultivationData.js | 境界名称、等级范围、突破条件、奖励表、曲线参数 |
| cultivationSystem.js | 标准化存档、计算修为速度、处理在线 tick、判断升级、判断突破、计算属性奖励 |
| characterPage.js | 显示境界卡片、进度条、突破按钮 |
| main.js / game.js 接入层 | 把在线 tick 和属性计算接入现有运行时 |

## 数据流

在线 tick：

```text
主循环 tick
  -> 检查是否可积累修为
  -> 计算 elapsed seconds
  -> 按每分钟修为换算本次增量
  -> 写入 cultivation.exp / totalExp
  -> 如果未处于突破卡点，自动升级
  -> 如果抵达突破卡点，停止跨级并提示可突破
  -> 触发轻量 UI 更新
```

属性计算：

```text
computeStats
  -> getCultivationBonuses(state.cultivation)
  -> 合并 hpPct / atkPct / matkPct / defensePct / drop / gold / skillDamage 等加成
```

突破：

```text
玩家点击突破
  -> 检查当前等级是否在 10/20/30...
  -> 检查条件
  -> 检查消耗
  -> 扣除材料/金币
  -> 更新 breakthroughLevel
  -> 解锁下一个大境界
  -> 允许继续升级
  -> 写日志和提示
```

## UI 设计

放在角色页，靠近“转生声望”和成长工作台。

卡片信息：

```text
境界：幻象境 Lv.36
修为：12,430 / 18,900
在线修行：14.8 / 分钟
下一突破：自动境，需要解锁困难难度
```

UI 元素：

- 境界名称和等级。
- 修为进度条。
- 在线修行速度。
- 当前加成摘要。
- 下一个突破条件。
- 到达突破点时显示“突破”按钮。

交互规则：

- 未到突破点时不显示突破按钮。
- 到突破点但条件未满足时，按钮禁用并显示缺少条件。
- 条件满足时，按钮可点击。
- 突破成功后写入日志，并显示短提示。

## 错误处理

1. 页面长时间后台挂起后恢复：只计算在线 tick 中实际经过时间，但不走离线收益入口。
2. 浏览器时间异常：单次 tick 的有效秒数设置上限，例如最多 60 秒，避免手动改系统时间刷修为。
3. 角色死亡：停止积累，恢复后继续。
4. 存档缺字段：标准化补齐。
5. 高阶突破条件依赖未实装材料：条件表可以返回“后续版本开放”，按钮禁用。
6. 达到 Lv100：停止积累修为，显示已达上限。

## 测试计划

单元测试：

- 旧存档能补齐 cultivation。
- 境界等级被限制在 1-100。
- 修为速度按地图、难度、转生正确计算。
- 暂停、死亡、离线不增加修为。
- 达到突破点后不能继续跨级。
- 突破条件不满足时失败且不扣材料。
- 突破成功后更新 breakthroughLevel 并扣除消耗。
- 每级属性和大境界奖励计算正确。

集成测试：

- 在线 tick 一段时间后修为增加。
- 修为满后自动升级。
- 角色页显示境界、进度、速度、突破条件。
- 境界加成进入 computeStats。
- 离线奖励不会增加境界修为。
- 旧存档加载后无报错。

手动验证：

- 新档打开角色页能看到初心境 Lv1。
- 在线 1-2 分钟后进度条推进。
- 用调试方式给足修为后能停在 Lv10。
- 满足条件后突破到 Lv11。
- 暂停游戏后修为停止。
- 角色死亡后修为停止。

## 接受标准

1. 旧玩家打开游戏不会丢档或报错。
2. 新玩家默认显示 `初心境 Lv.1`。
3. 在线时修为自动增长。
4. 离线收益不包含境界修为。
5. 小境界可自动升级。
6. 每 10 级必须突破，未突破不能进入下一大境界。
7. 境界属性能在角色属性中体现。
8. 角色页能清楚展示当前境界、修为进度、在线速度、下一突破条件。
9. `npm test` 和 `npm run check` 通过。

## V1 实现边界

V1 只实现系统底座：

- 存档字段。
- 在线修为 tick。
- 境界等级和突破。
- 境界属性奖励。
- 角色页展示。
- 测试覆盖。

V2 可以再考虑：

- 境界技能树。
- 境界称号。
- 高阶突破专属副本。
- 境界外观特效。
- 日常修行任务。
- 微信小程序在线奖励调优。
